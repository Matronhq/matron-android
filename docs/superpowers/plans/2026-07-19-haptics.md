# Haptics Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add three small foreground vibrations — a celebratory pop on QR link success, a short buzz on genuine link failure, and a soft tick when an agent turn completes.

**Architecture:** A single pure-Kotlin `Haptics` interface (`celebrate`/`error`/`tick`) is injected into the four view models that own the trigger edges. The concrete `SystemHaptics` wraps the platform vibrator and lives in `AppDependencies`; a `Haptics.None` no-op is the default so existing VM constructions and tests are unaffected. Triggers fire at the state-mutation sites and are unit-tested with a recording `FakeHaptics`.

**Tech Stack:** Kotlin, Jetpack Compose, Android `Vibrator`/`VibrationEffect`, kotlinx.coroutines, JUnit 4.

## Global Constraints

- Scope is `matron-android` only. No journal/relay/protocol changes.
- Foreground-only. No background/notification-channel vibration (push is a stub; out of scope).
- Add `<uses-permission android:name="android.permission.VIBRATE" />` to the manifest (install-time permission, no runtime prompt).
- Three semantic effects only, all short and restrained (never a fanfare):
  - `celebrate()` — light two-beat pop (soft tick → slightly firmer tap).
  - `error()` — one short buzz. Fires only on genuine failures, never on a deliberate decline.
  - `tick()` — one soft tick.
- On **API 31+** use `VibrationEffect.Composition` primitives; on **API 26–30** fall back to `createWaveform` / `createOneShot`. The split is quality parity only; it must not change the felt shape. minSdk is 26, compileSdk 35.
- Every effect is a no-op when `vibrator.hasVibrator()` is false. No in-app haptic settings/toggles (the OS haptic setting already governs).
- `Haptics` is a pure Kotlin interface with a `Haptics.None` no-op default; only `SystemHaptics` touches `Vibrator`/`VibrationEffect`.
- Trigger edges (fire once on the edge into the terminal state, never on re-observation):
  - `celebrate()` — `DeviceLinkViewModel` edge into `Phase.Approved`; `LinkSignInViewModel` edge into `State.SignedIn`.
  - `error()` — `DeviceLinkViewModel` edge into `Phase.Error`; `LinkSignInViewModel` edge into `State.Error`; `RendezvousSignInViewModel` edge into `State.Error`. **Not** `DeviceLinkViewModel.Phase.Denied` (a deliberate self-initiated decline stays silent).
  - `tick()` — `ChatViewModel.activityLabel` transition from non-null (working) to null (idle), only while observing, never on the initial snapshot.
- Build/test command: `JAVA_HOME=/opt/homebrew/opt/openjdk@17 ./gradlew testDebugUnitTest`.

```kotlin
package chat.matron.android.platform

import android.content.Context
import android.os.Build
import android.os.VibrationEffect
import android.os.Vibrator
import android.os.VibratorManager

/// Small, restrained foreground vibrations for meaningful moments. Pure Kotlin
/// so the view models that fire these can be unit-tested against a fake; only
/// [SystemHaptics] touches the platform vibrator.
interface Haptics {
    /// QR link succeeded — a light two-beat pop.
    fun celebrate()

    /// Genuine link failure — one short buzz. Never fired on a deliberate decline.
    fun error()

    /// Agent turn completed — one soft tick.
    fun tick()

    companion object {
        /// No-op default so a VM constructed without haptics (existing call
        /// sites, tests) does nothing rather than crashing.
        val None: Haptics = object : Haptics {
            override fun celebrate() {}
            override fun error() {}
            override fun tick() {}
        }
    }
}

/// Platform [Haptics] over the system vibrator. Every call is a no-op when the
/// device has no vibrator; the OS haptic setting is already honoured by the
/// vibrator itself. API 31+ uses crisp `Composition` primitives; API 26–30 uses
/// `createWaveform`/`createOneShot` shaped to the same feel. Effect amplitudes
/// are hand-tuned on device — the values below are the agreed starting point.
class SystemHaptics(context: Context) : Haptics {
    private val vibrator: Vibrator? =
        if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.S) {
            (context.getSystemService(Context.VIBRATOR_MANAGER_SERVICE) as? VibratorManager)?.defaultVibrator
        } else {
            @Suppress("DEPRECATION")
            context.getSystemService(Context.VIBRATOR_SERVICE) as? Vibrator
        }

    private val hasVibrator: Boolean = vibrator?.hasVibrator() == true

    override fun celebrate() {
        val v = vibrator ?: return
        if (!hasVibrator) return
        if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.S) {
            v.vibrate(
                VibrationEffect.startComposition()
                    .addPrimitive(VibrationEffect.Composition.PRIMITIVE_TICK, 0.5f)
                    .addPrimitive(VibrationEffect.Composition.PRIMITIVE_CLICK, 0.8f, 60)
                    .compose(),
            )
        } else {
            v.vibrate(
                VibrationEffect.createWaveform(
                    longArrayOf(0, 25, 60, 40),
                    intArrayOf(0, 90, 0, 160),
                    -1, // -1 = do not repeat
                ),
            )
        }
    }

    override fun error() {
        val v = vibrator ?: return
        if (!hasVibrator) return
        v.vibrate(VibrationEffect.createOneShot(60, 180))
    }

    override fun tick() {
        val v = vibrator ?: return
        if (!hasVibrator) return
        if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.S) {
            v.vibrate(
                VibrationEffect.startComposition()
                    .addPrimitive(VibrationEffect.Composition.PRIMITIVE_TICK, 0.5f)
                    .compose(),
            )
        } else {
            v.vibrate(VibrationEffect.createOneShot(20, 60))
        }
    }
}
```
